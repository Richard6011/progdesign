# 第二版验证记录

验证日期：2026 年 11 月 16 日。对象：`GitHub/SRC_v2` 的基础 C 单人版本。

## 编译

本机使用 Visual Studio MSVC 14.44 和 Windows SDK 10.0.26100，以 C17 编译。启用 `/W4 /WX`，将警告作为错误；最终图形程序和核心测试均编译通过，无编译警告。使用 `/MT` 静态链接 C 运行库。

最终可执行文件为本目录下的 `NoteCollisionV2.exe`。不需要 EasyX、Qt 或 C++ 桥接文件。

## 核心测试

执行构建测试脚本（整理后的路径为 `tools/build.ps1 -Action Test`），最终输出：

```text
PASS: 2478 checks; six real charts; accounts, scores, settings and real silent audio.
```

实际验证包括：

- Perfect、Great、Good、Miss 的正负时间边界及相邻值；输入校准、重复按住、非法轨道。
- 长按头部不重复计分、精确尾部松开成功、过早松开漏击、重复刷新不重复结算。
- 暂停时音乐判定时间冻结；有活动长按时必须重新按住才能恢复。
- 《小星星》和《霓虹脉冲》的六份转换谱面全部读取成功，并以理想按键事件完整回放，全部满分、没有漏击。
- 混合判定的 525,000 分、S 级连击要求、权重和统计关系校验。
- 已知 SHA-256 测试向量、中文账号注册登录、密码首尾空格、错误密码、重复账号及不保存明文密码。
- 成绩跨文件读回、同账号同榜单只保留最佳成绩、同难度过滤、降序排序以及未完成成绩拒绝保存。
- 损坏账号、成绩、设置文件保留原样；非法设置不覆盖原值。
- 使用真实 Windows 音频设备进行零音量短暂播放，确认位置增加、暂停冻结和恢复继续。

测试使用 `tests/run_进程号_时刻` 目录，未读取或修改正式 `data` 存档。

## 本次放宽判定窗口

完美、优秀、良好窗口由 ±90/150/220ms 放宽到 ±150/250/350ms，自动漏击使用相同的最大窗口。本次已复跑上述核心测试，共 2,478 项通过，包含正负 350ms 边界、351ms 越界、正负 200ms 校准以及长按尾部已过时不能补按头部。界面操作说明和最终 EXE 已重新编译。

## 基础版本实际窗口测试

执行 `tests/界面测试.ps1`，最终输出：

```text
UI PASS: 75 checks.
```

测试实际创建 Windows 图形窗口并操作控件，完成如下路径：

1. 注册测试账号，注册成功后返回登录状态。
2. 用错误密码尝试登录，确认出现错误提示并停留在登录页面。
3. 使用正确密码进入主菜单。
4. 从设置界面将音乐音量保存为零、偏移保存为 25ms，并核对实际文件。
5. 打开操作说明、排行榜、歌曲选择和难度选择，确认逐页切换。
6. 加载小星星简单谱面，经过三秒倒计时开始真实音频播放。
7. 实际点击暂停、请求继续，并捕获窗口图像。
8. 完整播放整首歌曲，不击打任何音符；自然结算为 43 次 Miss，保存一条完整测试成绩。
9. 打开排行榜，确认测试账号记录可显示。
10. 退出登录，确认账号输入框清空，再关闭本次测试窗口。

界面测试仅使用 `ui_test_data`，不会生成正式账号。当时在 `build/ui_checks` 生成了 13 张窗口截图和结果 JSON；已检查登录、主菜单、游戏、暂停、结果和排行榜的截图，没有发现文字重叠或按钮缺失。整理目录时已删除这些可再生成的测试截图、测试账号及临时文件；本记录保留历史验证结果。

## 可读性核对

生产源码为 7 个 `.c` 文件和 2 个 `.h` 文件，共 1,912 个物理行，排除空白和纯注释后为 1,800 行。另有一个 380 行的 C 核心测试文件。

每个非空 C 代码行均带中文注释。主体共有 88 个函数，Lizard 静态圈复杂度平均 5.47、中位数 4.5、最高 27。接口及页面操作按职责分开，不再包含原版的 126 复杂度网络消息处理函数。本版暂不包含联机，因此两版统计的功能范围不同。

完整逐文件及逐函数数据见本文件同目录下的 `readability_metrics.json`。
