# 音符碰撞 基础 C 单人第二版

本版是独立的单人学习版本，源码及运行文件集中放在 `SRC_v2` 文件夹。原仓库的 `src` 保留原样，第二版通过独立分支提供。

目录已经按用途整理：根目录放游戏源码和启动程序，其他内容分开保存。

```text
SRC_v2/
  NoteCollisionV2.exe   图形游戏程序
  运行.bat             双击启动游戏
  README.md            使用和源码说明
  *.c、*.h             游戏源码和头文件
  assets/              音乐和谱面资源
  data/                正式账号、设置和最佳成绩
  tools/               编译、测试入口和谱面转换工具
  tests/               可复用的测试代码
  docs/                验证记录与复杂度统计
```

按本次确认的范围，先完成单人游戏，**暂不加入双人 PK**。界面采用 Windows 自带的窗口、按钮、输入框和 GDI 绘图，不需要 EasyX、Qt 或 C++ 文件。使用固定数组、普通结构体、`if`、`for`、`while` 和文本文件，优先方便阅读。

## 直接打开界面

双击本文件夹中的 **`NoteCollisionV2.exe`**，或双击 **`运行.bat`**。

可执行文件已经在本机编译完成。运行时请保留同级 `assets` 文件夹，不能只把 EXE 单独移走。程序面向 Windows 10/11 x64，编译时静态链接 C 运行库。

仓库的 `releases/NoteCollisionV2-Windows-x64.zip` 同时包含 EXE、源码、音乐谱面和工具。下载后完整解压，双击其中 `SRC_v2/NoteCollisionV2.exe` 即可运行；分发包不含任何真实账号、密码摘要或个人成绩，首次使用需要自行注册。

第一次运行没有默认账号：

1. 在登录页点击“没有账号，去注册”。
2. 输入账号、密码和确认密码，注册成功后返回登录页。
3. 输入密码登录，进入主菜单。
4. 点击“开始单人游戏”，先选歌曲，再在下一页选难度。
5. 三秒倒计时后音乐和音符开始运行。

账号区分大小写，支持中文；账号上限为 16 个 UTF-16 单元，密码上限为 64 个 UTF-16 单元。账号首尾不能有普通空格，密码首尾空格会原样参与验证。密码保存为随机盐和 SHA-256 摘要，不保存明文。

## 游戏操作

| 操作 | 按键或方法 |
| --- | --- |
| 四条轨道 | 从左到右为 `D / F / J / K`，建议切换到英文输入状态 |
| 单点音符 | 蓝色短条到达红色判定线时按下 |
| 长按音符 | 绿色头部到线时按住，保持到尾部到线后松开 |
| 连续节点 | 按节奏分别击打紫色节点 |
| 双押或三押 | 同时按多个对应键，各音符独立判定 |
| 暂停 | `Esc` 或点击“暂停 / 继续” |
| 继续 | `Enter` 或再次点击按钮；活动长按必须重新按住 |
| 中止 | 点击“中止，返回选曲”，本局不保存 |
| 窗口失去应用焦点 | 演奏中自动暂停，避免切出后额外漏击 |

判定窗口已放宽为完美 ±150ms、优秀 ±250ms、良好 ±350ms。也就是说，音符到达红线前后 0.35 秒内按下，仍有机会命中；长按必须在尾部到达之前开始，并保持至尾部。各等级权重依次为 1000、700、400、0，满分一百万分。S 级需要准确率至少 95%，且最大连击覆盖至少 80% 的谱面音符。长按只在最终完成时计一个音符，不把头部重复计算。

这三个判定时间统一定义在 `game.h` 的 `PERFECT_WINDOW_MS`、`GREAT_WINDOW_MS`、`GOOD_WINDOW_MS`，命中判定和超时漏击共用这些值，避免修改一处后另一处仍按旧窗口处理。

自然播放完成会生成完整结果并处理排行榜。每个账号在“同一歌曲、同一难度”下只保留最高分，相同或较低成绩不覆盖旧最佳。排行榜同分并列，列表可以滚动查看全部账号。中止、关闭窗口或音乐异常停止都不会保存未完成成绩。

“准确率”内部直接使用百分数 0~100；与原仓库的 0~1 表示不同。阅读代码时注意这个变化。

## 存档位置和格式

所有正式文件都在 **本程序所在文件夹的 `data` 子文件夹**，不使用 `%APPDATA%`，也不读取或覆盖原版账号与成绩。

当前完整路径是 `C:\Users\zouji\Desktop\程序设计\GitHub\SRC_v2\data`。这个文件夹已创建；在没有注册账号、保存设置或完成游戏之前，对应的文本文件尚不存在，这是正常情况。

| 文件 | 内容 |
| --- | --- |
| `data/accounts.txt` | 格式版本头；之后每行是账号、随机盐、密码摘要，以制表符分隔 |
| `data/scores.txt` | 格式版本头；之后保存账号、歌曲、难度、总音符数、各判定数量、最大连击和时间 |
| `data/settings.txt` | 格式版本、音乐音量和输入校准偏移 |

文件写入先经过同目录临时文件，再替换正式文件。读取发现损坏账号或成绩时保留原文件，不用空数据覆盖。设置损坏时使用默认值，但本次运行不允许覆盖损坏设置；可以先备份并检查该文件，再重新启动程序。

本版没有旧版存档迁移功能，不能把原版 JSON 或源文件2的明文账号表直接改名放进来。账号最多 100 个，最佳成绩最多 200 条，每份谱面最多 2,000 个音符。这里使用固定容量，是为了便于初学者理解数组边界。

## 建议按什么顺序读代码

| 文件 | 用途 |
| --- | --- |
| `game.h` | 先看数据结构：音符、谱面、统计、游戏、账号、成绩和设置 |
| `engine.c` | 纯游戏规则：判定窗口、长按、漏击、连击、得分和暂停恢复 |
| `assets.c` | 使用 `fopen`、`fscanf` 读取简单整数文本谱面，并做基础校验 |
| `storage.c` | 使用普通数组及文本文件完成注册登录、最佳成绩和设置保存 |
| `crypto.c` | 将系统随机数和密码摘要接口放在独立文件，游戏规则不依赖其内部细节 |
| `audio.c` | 用 Windows MCI 播放已有 WAV，并查询真实音乐位置 |
| `ui.c` | 每个页面用独立函数显示，每类页面用自己的按钮处理函数 |
| `ui.h` | 只声明窗口程序入口 |
| `main.c` | 确定 EXE 所在目录、选择数据目录，再调用图形界面 |
| `tests/test_basic.c` | 使用普通 `check` 函数测试，不使用 CHECK 宏 |

源码的每个非空 C 代码行都有中文注释。GUI 所需的窗口过程回调、设备句柄以及系统密码摘要接口仍是 Windows API 的必要部分；它们被集中放在界面、音频和密码文件中，读游戏规则时可以先跳过这些系统细节。

## 音乐和谱面

保留共同维护仓库的《小星星》和《霓虹脉冲》，每首各三个难度。音频原样复制，六份谱面仅将 JSON 转成易于阅读的整数文本，没有重新生成音符或改动歌曲节奏。原资源说明也保留在 `assets` 中。

例如，`assets/song0_0.txt` 第一行是：

```text
43 33800 2400
```

分别表示 43 个音符、音乐时长 33,800ms、移动时长 2,400ms。之后每行七个整数依次是：

```text
编号 类型 轨道 头部时刻 尾部时刻 连续分组 同时按键分组
```

类型 0、1、2 分别表示单点、长按、连续节点；无分组时为 -1。文件按头部时刻、轨道和编号排序。双押和三押仍然由同一时刻不同轨道的多个音符组成。

需要从原仓库重新转换时，可执行 `tools/convert_charts.ps1`。正常玩游戏不需要运行转换脚本，也不需要 Python。

## 重新编译和测试

进入 `tools` 文件夹，双击 `build.bat` 重新编译，双击 `test.bat` 编译并运行核心测试。

构建脚本会寻找本机 Visual Studio 的 C 工具，使用 Windows SDK，以 C17 编译所有 `.c` 文件，并启用 `/W4 /WX`，编译警告会作为失败处理。当前电脑上的 Visual Studio 和 SDK 已经适配，不沿用原仓库作者的 MinGW 绝对路径。无需改动 VS Code 的全局配置。

也可以在本文件夹的 PowerShell 中执行：

```powershell
.\tools\build.ps1 -Action Build
.\tools\build.ps1 -Action Test
.\tests\界面测试.ps1
```

如果 Windows PowerShell 提示脚本策略限制，可使用与 BAT 相同的调用方式：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1 -Action Test
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\界面测试.ps1
```

核心测试会短暂打开真实音乐设备，音量为零。每次核心测试使用 `tests/run_进程号_时刻` 独立目录。界面测试会打开自己的程序窗口，注册测试账号并实际完成一首零音量歌曲，使用 `ui_test_data`；它不会修改正式 `data` 目录。运行界面测试期间请不要手动操作该测试窗口，约四十秒后会自行关闭。

整理时已删除旧的 `build` 构建产物、窗口截图、`tests/run_*` 临时目录以及 `ui_test_data` 测试账号。它们都可以重新生成，不影响正式游戏；再次编译或测试后出现这些目录属于正常情况。验证说明保留在 `docs/测试记录.md`。

## 复杂度变化

按 Lizard 静态统计，第二版主体函数平均圈复杂度约 5.47，最高为 27；原版主体平均约 8.60，最高为 126。原版有联机模块，而新版按本次确认暂不包含，因此这不是相同功能量下的性能对比。

更有意义的变化是：不再有一个同时处理各种账号、页面和游戏动作的大分发函数，而是按页面拆开；新界面的 `on_command` 只负责分流，圈复杂度为 14。多数游戏规则函数可以独立阅读和测试。完整指标保存在 `docs/readability_metrics.json`。
