# 本机部署

## 配置开发环境

在 Windows x64 上使用 Qt 6.8 系列的 MinGW 64 位组件、GCC/G++ 13.1.0（MSVCRT、POSIX、SEH）、CMake 3.31.10 和 Ninja。使用 VS Code 调试时还需要 MinGW 工具包配套的 GDB。

从项目根目录按 README 的开发环境说明运行配置脚本。脚本会在项目的 `.local` 下为 MinGW、Qt、CMake 和 Ninja 建立目录链接。工具的安装位置不同时，运行脚本时传入本机的安装根目录。构建脚本、CMake 预设和 VS Code 共同使用这些链接。 [开发环境说明](../README.md#开发环境)

## 构建与调试

- 双击`构建.bat`生成 `build/debug` 下的 `NoteCollision.exe`。
- 在 VS Code 中打开项目根目录并选择 `c-debug` 预设。按 `Ctrl+Shift+B` 构建，按 `F5` 构建并启动 GDB。可在 `src/main.c` 的 `main` 函数处按 `F9` 设置断点。
- 从工程内的 `build/debug` 或 `build/release` 普通运行时，`accounts.json`、`records.json` 和可选的 `settings.json` 位于工程根目录。`F5` 使用 `.local/debug-data`，也可用 `--data-dir` 指定其他数据目录。

## 制作与运行发行包

在项目根目录运行以下命令生成 Release 发行包。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Development.ps1 -Action Package -Configuration Release
```

脚本使用 `windeployqt` 收集 Qt DLL、Windows 平台插件和 MinGW 运行库，并把游戏资源和许可说明一同装入 `out/NoteCollision-Qt-Windows-x64.zip`。

在目标电脑完整解压后运行 `NoteCollision.exe`，并保留程序旁的 DLL、`platforms` 和 `assets`。目标电脑无需安装 Qt SDK。独立发行包默认使用 `%APPDATA%/NoteCollisionC` 存放用户数据。 [运行与玩法](../README.md#运行与玩法)
