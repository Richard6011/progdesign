# 《音符碰撞》局域网联机答辩稿

内容对应 Windows x64 版的联机协议 5。正文之后可打开源码，再演示两台电脑如何建房、独立开局并互看比分。

## 一、口述正文

《音符碰撞》的双人模式让两名玩家在相同的曲目和难度下各自演奏。房主创建 TCP 监听，客人输入房主的 IPv4 地址和端口加入。连接后双方交换昵称，大厅里显示对方的名字。

房主决定歌曲与难度，程序把选择发给客人。客人自动加载本地对应的谱面和音乐，加载成功后可以开始。若缺少文件或加载失败，客人会看到提示，开始入口保持禁用。房主在开局前可以换曲，任一方开始后选曲锁定。如果换曲消息与客人的开始操作交错，客人会收到提示并按房主的新选择重新加载。

两个人各点自己的“开始”。每台电脑使用本地音乐位置推进音符、判定按键并计算分数。网络在演奏中定期传送当前累计分，画面会显示对方最近的比分。各自完赛时把最后的分数作为最终分发送。先结束的一方可以留在结果页看对方的比分继续变化。本机完赛且收到对手最终分后，本机显示双方最终分并保存一次本机成绩。

网络和游戏在同一个主循环里更新。连接、收发都使用非阻塞 socket，每次轮询只推进当前可做的工作。任一方可以退出，连接中断时会提示，程序负责关闭连接并释放相关资源。下一局重新建房加入。

## 三、现场演示顺序

1. 两台电脑打开同一新版并登录各自的演示账号。房主创建房间，客人填房主的局域网 IPv4 地址和端口，默认端口为 `9527`。
2. 展示双方昵称。由房主选择《小星星》Easy，给老师看客人的曲目和难度如何自动更新。
3. 让一方先点开始，另一方稍后开始。演奏几组音符，指出各自画面上的对方累计分。
4. 先结束的一方留在结算页，等另一方完成，展示两人的最终分。
5. 展示主动退出和对方收到的提示。需要再玩时重新创建并加入房间。

单机排练可以开两个窗口，客人填 `127.0.0.1`。两个实例分别用 `--data-dir` 指向独立目录，避免同时操作同一份账号和成绩文件。两台电脑演示时，使用房主所在局域网可达的 IPv4 地址。《小星星》Easy 的曲目约 34 秒，完整结算可预留一分钟。 [联机操作说明](../README.md#局域网双人)

## 四、备答

| 问题 | 回答 |
| --- | --- |
| 为什么用 TCP？ | TCP 按发送顺序交付字节。应用层在缓冲区里识别消息边界，按顺序处理选曲和比分。 |
| 一次 `send()` 或 `recv()` 可以完成一条消息吗？ | 返回值表示本次实际处理的字节数。发送不足时保留剩余数据，接收不足时继续积累，收到完整消息再解析。 |
| 对手比分更新慢会影响判定吗？ | 画面上的对手分数可能稍晚更新。自己的音符和得分由本地播放位置和按键决定。 |
| 两台电脑怎么使用同一首歌？ | 客人按房主发送的曲目和难度自动加载自己电脑上的资源。两端运行同一新版发行包，使用随包提供的曲库。 |
| 已完赛时对手还在演奏怎么办？ | 自己的最后得分已经确定，界面继续接收并显示对手的累计分。收到对手的最终分后就能显示双方最终分。 |
| 连接断开怎么处理？ | 主动退出会通知对方。若接收端读到连接已关闭，或收发遇到连接错误，程序会提示并清理 socket。 |
