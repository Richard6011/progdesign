# 实现与验证记录

日期：2026-11-16。需求依据为同目录的《音符碰撞总体开发文档》v0.2；该文档由另一位 agent 持续维护，此记录描述本次实际实现和运行证据。

## 已实现

| 模块 | 当前行为 |
| --- | --- |
| 基础工程 | C++17、Qt Widgets/Multimedia/Network、CMake/Ninja；复用 VS Code“程序设计”Profile 中已安装的 Qt 6.8.3 和 MinGW 13.1 |
| 玩法 | D/F/J/K 四轨、单点、严格尾部长按、独立连锁节点、双押/三押；可注入时间验证判定窗口和输入偏移 |
| 计分 | 唯一最终判定、100万归一化分数、准确率、Combo/最大Combo、S/A/B/C/D、FC/AP |
| 单人闭环 | 选曲/难度、媒体预加载和倒计时、实际播放态时钟锚点、暂停及活动长按重新按住、重开、自然媒体结束后结算 |
| 文件 | 路径边界及谱面严格校验、SHA-256、QSaveFile 原子保存、同局去重、按模式/谱面/规则分榜、同分并列、损坏文件保护、设置保存 |
| 联机 | 两人 TCP 房间、手输IPv4、资源校验、双方准备、五次时钟采样、ARM/COMMIT、约100ms比分、FINISH与结果确认、中止和心跳超时 |
| 界面 | 主菜单、准备、房间、游戏、结算、排行、设置、帮助；绘制只读核心状态，控制器位于 MainWindow |
| 资源 | 原创36秒WAV《霓虹脉冲》；Easy/Normal/Hard分别68/84/136个判定单元，每档包含四种表现形式 |

`GameEngine::finished()` 只表示音符都已结算，界面还必须等媒体自然 EndOfMedia 后才能生成正式成绩。联机必须再完成 RESULT_ACK / RESULT_CONFIRMED，任意未确认或中止局都不能入榜。

根 `tests/CMakeLists.txt` 注册六个独立可执行测试。所有文件测试使用临时目录，UI 音频测试静音，正式用户成绩不受影响。

| --- | --- |
| core_tests | ±45/90/140ms及相邻边界、正负输入偏移、自动重复、空按、长按尾/早松、连锁漏击、同时键、六音符900000分案例、暂停恢复/取消恢复、延迟帧结算次序、计数/评级和事件幂等 |
| storage_tests | 三档谱面与资源、路径越界、非法轨道、成绩重读、幂等保存、每昵称最佳、1/1/3名次、单双人分榜、旧版Solo迁移、无效/未确认成绩拒绝、损坏文件保护、设置往返及越界 |
| NetworkTests | 半包/粘包、非法帧、协议字段、五采样、资源不符、角色权限、房间人数、准备/配置、同步开局、快照、最终结果、平局、退出、确认后断线保留；错开两端Started时的首个比分竞态回归 |
| NetworkReviewTests | 原始socket发送旧配置/旧对局消息、资源不一致后在原连接重试、重复最终回执及确认幂等 |
| UiSmokeTests | 真实QApplication及QMediaPlayer：起播、暂停冻结与恢复、同曲重新加载、36秒自然结束全Miss、自动保存、fresh仓库与UI排行；Loaded=2、Started=3、Ended=1 |
| UiLanTests | 本机两客户端真实TCP及媒体：预加载、准备、开局、36秒整曲、双方确认、各存本方一条、重读分榜、同曲再战、倒计时退出不保存；Loaded=2/2、Started=1/1、Ended=1/1 |

最终运行结果以 `build/qt-debug/Testing/Temporary/LastTest.log` 和 `build/qt-debug/test-results.xml` 为准。截图位于 `build/evidence/ui-home.png`、`ui-game.png`、`ui-result.png`，已经检查中文字体、键位和主要布局。

本次实际修复了三个有回归证据的问题：延迟帧下长按与Miss批量结算次序改变Combo；相同媒体重开不一定再次收到LoadedMedia；一端已起播而另一端尚在Countdown时收到首个SCORE_SNAPSHOT被误判非法。分别通过按生效时间排序、重新设置媒体源、校验后丢弃本机起播前快照处理。

## 工作目录和版本管理

Git仓库位于 `code`，分支 `main`，提交信息使用中文；构建与打包输出忽略，不提交自动生成文件。

按用户新要求，开发入口切到 `C:/Users/Administrator/Desktop/progdesign/code`，“程序设计”Profile 默认项目目录同步更新。Windows因当前应用工作目录句柄占用拒绝原地重命名，因此 `progdesign` 目前仍是目录联接。关闭占用后，从外部PowerShell运行 `tools/Rename-Workspace.ps1` 才会完成物理重命名；脚本失败时恢复访问入口。该剩余项不能标记为已完成。
